**Coordinator kit and projects-root hooks (2026-11-17):** `skills/coordinator-kit` is a repo skill (12 skill folders; `./skills/` is what the Cursor manifest and the zip packer scan). Claude hooks are `hooks/hooks.json`: `projects-root-guard.ps1` on PreToolUse (Write, Edit, NotebookEdit, Bash, PowerShell) and `projects-root-report.ps1` on Stop, both with `${CLAUDE_PLUGIN_ROOT}`. Cursor plugins do support hooks (`https://cursor.com/docs/reference/plugins`, `https://cursor.com/docs/hooks`). Their file shape is not Claude's, and a set `hooks` path replaces discovery of `hooks/hooks.json`, so `.cursor-plugin/plugin.json` points at `hooks/cursor-hooks.json` (`preToolUse`, `stop`, `${CURSOR_PLUGIN_ROOT}`). A live Cursor install was not run. The projects root is `WORKSTATION_PROJECTS_ROOT` when that path exists, else `C:\projects` when it exists, else `%USERPROFILE%\projects`. No root: the hooks allow and stay quiet. `WORKSTATION_PROJECTS_DENY_KEYWORDS` is optional and defaults to empty, so the old project word list does not ship. Deny and report text points at the root `AGENTS.md`.

**Cursor permission without hard blocks, portable hook launcher (2026-11-18):** owner rule: agents write and keep sources of truth, verified deliverables, SPEC and protected paths, only with the owner's explicit yes, and checks prove each edit; the one hard block is another branch's `STATE-<slug>.md`. Cursor does not enforce "ask" in `preToolUse` (`https://cursor.com/docs/hooks`), so `protected-files-guard` answers Cursor with allow plus a warning (the yes it needs, the report it owes, the checks that will run); the unlock command asks in Cursor `beforeShellExecution`, where "ask" is enforced. Claude stays "ask". The plugin ships the always-on Cursor rule `rules/sot-permission.mdc` (manifest `rules`). Every Claude hook command runs through `hooks/run-ps.sh` (powershell, else pwsh, else a silent exit 0), so Linux and WSL sessions no longer show a hook error. Cursor commands still call `powershell` directly: `sh` is not on the Windows PATH Cursor may use.

**SoT guard (2026-11-19, branch `state-migration/sot-guard`, stacked on `state-migration/cursor-permission`):** per-repo registry `.claude/sot.json` (JSON; schema in `scripts/state/README.md`) and `scripts/state/sot_guard.py` (`match`, `after-edit`, `check`, `lint-registry`). `protected-files-guard` treats listed SoT and the registry as protected and names their checks; the new `sot-after-edit.ps1` (Claude PostToolUse, Cursor postToolUse) runs the fast checks and lists changed CSV cells; the git pre-commit pack runs `check` as the hard correctness gate; derived files edited by hand warn after the edit and fail the check. state-init adds registry entries; iterative-cleaning runs `lint-registry`.

**Instruction-file warning (2026-11-17):** Claude `hooks/hooks.json` runs `hooks/agents-md-only-warn.ps1` on SessionStart. The command runs through `hooks/run-ps.sh` (powershell, then pwsh, else silent) with `${CLAUDE_PLUGIN_ROOT}`. It scans the session directory and every parent up to the drive root for `CLAUDE.md`, `.claude/CLAUDE.md`, and `CLAUDE.local.md`. It ignores `~/.claude/CLAUDE.md`. A hit prints the path list and Dan's rule: fold the file into `AGENTS.md`, then delete it (in a PR for repo files; files outside a repo: tell Dan). Warn only: it never deletes, edits, or blocks, and it exits 0 on every error. No Cursor variant (pending decision C1). `hooks/cursor-hooks.json` is unchanged. This PR does not change any PC.
